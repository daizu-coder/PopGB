# PopGB 技術メモ(SHARP Brain / Windows CE)

PopGB を作る中でわかったことのうち、実機で確かめたことと、このリポジトリのコードで裏付けが取れることだけをまとめています。Brain 向けにほかのエミュレータを移植するとき、作業を始める前に AI に読ませることを想定しています。

実機で確かめた機種は SHARP Brain PW-G5300 だけです。ほかの機種での動作は確かめていません。

各項目の最後の( )は、もとにした開発メモの記録です。開発メモはリポジトリに入れていません。

v1.0.0 より前の直しは、コミット 29fd5e8(フロントエンド)と 31ed25b(コアのフック)にまとめて入っています。

## 全体の作り

- gnuboy は libretro コアではありません。`Makefile.ce` は上流の `Rules` を読み込まず、コアのファイル(CPU・画面・音・メモリ・ローダーなど)と `sys/ce/` のフロントエンドだけをリンクします。上流の `main.c`・`menu.c` などは使いません(開発メモの「実装したファイル一覧」)
- `ce_main.c` の `WinMain` は、`emu_run()`(`emu.c`)とメインメニューを行き来します。`emu_run()` は1フレームごとに `doevents()`(`ce_main.c`)を呼びます。画面をタップすると、`doevents()` が `emu_pause(1)` で `emu_run()` から戻らせます。メニュー・ROM の切り替え・ステートセーブは、`emu_run()` の外(`WinMain` のループ)で行います(開発メモの「重要な設計メモ」)
- コアで変えたファイルは [`LICENSING.md`](LICENSING.md) の2節にまとめています
- `AppMain.exe` が使う DLL は `COREDLL.dll` だけです。`arm-mingw32ce-objdump -p AppMain.exe` で確かめられます(開発メモの「v1.0.4 の1回目」、2026-10-09)

## ビルド

- cegcc の `signal.h` は、`__COREDLL__` が定義されていると `#include_next <signal.h>` をします。その先に `signal.h` が無いので、コンパイルが止まります。`Makefile.ce` で `-I./sys/ce/compat` を先に置き、`sys/ce/compat/signal.h` を読ませて避けています
- `Makefile.ce` は `-march=armv5te -mno-unaligned-access` と `-DIS_LITTLE_ENDIAN -DALT_PATH_SEP` を付けています

## 画面

- GAPI(`gx.dll`)は使っていません。ほかに試した2つは、実機で使えませんでした(開発メモのセッション20)
  - `ExtEscape(GETRAWFRAMEBUFFER)` は 0 を返しました
  - `ddraw.dll` の `DirectDrawCreate` は見つかりました。ただ、DirectDraw のオブジェクトを作ってから画面を Lock するまでの呼び出しを入れると、ROM 選択画面が出る前にアプリが落ちました。どの呼び出しで落ちたかはわかっていません。cegcc には `ddraw.h` がありません
- 画面の大きさは 480×320 でした(実機のログ)。今のコードは `GetSystemMetrics(SM_CXSCREEN / SM_CYSCREEN)` で取っています(開発メモのセッション19、2026-08-24)
- 描画は GDI だけでしています。画面と同じ大きさの RGB565 の DIB セクション(`CreateDIBSection`)に自分で拡大して書き、`BitBlt` で等倍のまま画面へ送ります(`ce_video.c` の `BlitToScreen()`)(開発メモのセッション20)
  - 拡大を `StretchDIBits` に任せた版は、実機で動かしたときに体感で遅く感じられました。自分で拡大して等倍の `BitBlt` で送る形に変えたら、体感では速さが戻りました。どちらも時間は測っていません(開発メモのセッション20)
  - DIB は `BI_BITFIELDS` と 5-6-5 のマスク(0xF800 / 0x07E0 / 0x001F)を付け、`biHeight` を負にして上から下の順にしています。この形で色が正しく出ることを実機で確かめました(開発メモのセッション20)
- GDI でウィンドウに直接描くので、ダイアログを閉じたあとの `WM_PAINT` で描き直します(`CeVideoForceRepaint()`)。これで、ダイアログを閉じたあとにゲーム画面が戻ることを実機で確かめました(開発メモのセッション20)
- gnuboy には 160×144 のまま描かせます(`fb.delegate_scaling = 1`、`scale` は 1)。拡大はフロントエンドだけでします(開発メモのセッション5、2026-08-18)
- `fb.enabled` は 1 のままにしています。`lcd.c` の `lcd_refreshline()` は、`fb.enabled` が 0 だと先頭で戻ります。そのため、`fb.enabled` をフレームスキップに使うと、コアの描画そのものが止まります。フレームスキップでは、画面への転送(`BlitToScreen()`)だけを飛ばします(開発メモのセッション14)
- カラーフィルターを切り替えたときは、`lcd.c` の `pal_dirty()` を呼びます。呼ばないと、切り替えても画面の色が変わりませんでした(実機)。`lcd.c` が色を計算し直すのは、ゲームがパレットを書いたとき(`pal_write()`)と `pal_dirty()` のときだけです(開発メモのセッション22、2026-08-25)

## 速さ

- 実機のログ(フレームスキップ 5)では、1フレームの時間のうち、CPU と画面の描画(`cpu+lcd`)が 50〜55%、音の合成(`apuMix`)が 1〜3% でした(開発メモのセッション19、2026-08-24)
- 拡大して書くときは、2画素を32ビットで1回に書きます。x2 では同じ画素を2つ並べて書き、2行目は1行目の写しにします。どちらも、実機で表示が正しいことと、体感で遅くなっていないことを確かめました。書き込みの時間は測っていません(開発メモのセッション23とセッション26)
- 表示の大きさごとに1分強ずつ取った実機のログでは、40ms を超えたフレームの数が、書く画素の数が多い表示ほど多くなりました(x1 < x2 < Wide < Full)(開発メモのセッション26)
- フレームスキップ中に、飛ばしたフレームを足し合わせて平均する処理を入れたら、その処理に画面の転送と同じくらいの時間がかかり、速くなりませんでした(実機のログ)。今は入れていません(開発メモのセッション16、2026-08-24)
- ログの書き込み(`CeLog()`)が毎回ファイルを開いて閉じていたとき、1回で 651ms かかったことがありました。ファイルを開いたままにして毎回 `fflush()` する形に変えたあとは、最大 2ms でした(実機のログ)(開発メモのセッション19、2026-08-24)
- デバッグログを ON にすると、60フレームごとに `perf: retro_run avg=… max=… blit avg=… max=…` の行が出ます(開発メモのセッション29)。`-DCE_PERF_DIAG` を付けてビルドすると、区間ごとの時間を測るコード(`sys.h`・`emu.c`・`sys/ce/` の `#ifdef CE_PERF_DIAG`)も入ります(開発メモのセッション16、2026-08-24)

## 音

- gnuboy の `sound.c` は、作った音を `pcm_submit()` に渡します。`emu.c` の `emu_run()` は、`pcm_submit()` が 0 を返したときだけ待つ作りです。`pcm_submit()` がほぼ毎回 1 を返していたときは、1フレームが約 170ms(本来の約10倍)になりました。実機のログで、この待ちの処理に入っていないことがわかりました(開発メモのセッション8)
- 今のコードでは、`pcm_submit()` はリングバッファにコピーするだけで、`waveOutWrite()` は別のスレッド(`CeAudioThreadProc`)がします(開発メモのセッション8)。フレームの速さは `doevents()` で決めます(waveOut が開けているときはリングにたまった量、開けていないときは `GetTickCount()` で)(開発メモのセッション32)
- リングの大きさは Sound Config で 32 / 64 / 128 / 256 KB から選べます。既定は 64 KB です(開発メモのセッション27とセッション28)
- Rate を変えるときは、`pcm.hz` を書き換えて `sound_reset()` を呼び、waveOut を開き直します。gnuboy はその周波数で音を作るので、周波数の変換はしていません(開発メモの「実装したファイル一覧」)
- メニューを開くと `pcm_pause(1)` でリングを空にするので、ゲームを始めるときとメニューから戻るときは、リングが空です。実機のログでは、音が途切れた(リングが空になった)のはこの直後の1回だけで、そのときの `retro_run` は平均 6〜8ms でした。今のコードは、`emu_run()` を呼ぶ前に 120ms 分の無音をリングに入れます(`CeAudioPrimeSilence(120)`)。無音を入れたあとの動作は確かめていません(開発メモのセッション32)

## 入力

- キーは `GetAsyncKeyState` で毎フレーム読みます。既定は、矢印 = 十字キー、Enter = A、Backspace = B、Tab = セレクト、M = スタートです(`ce_input.c`)(開発メモの「実装したファイル一覧」)
- 斜め(右上など)の行は、1つのキーで2方向を押します。全部のキーの分を OR でまとめてから、ボタンごとに `pad_set()` を1回だけ呼びます。行ごとに `pad_set()` を呼ぶと、同じボタンを持つあとの行が前の行を打ち消すためです。斜めの入力が効くことを実機で確かめました(開発メモのセッション9、2026-08-18)

## ダイアログ

- `MessageBoxW()` で出した日本語は□になりました。日本語を出すところは、自前のダイアログ(`IDD_MSGBOX`・`IDD_CONFIRM`)にビットマップフォントで描いています(開発メモのセッション22、2026-08-25)
- メインメニューの中から出した `MessageBoxW()` が見えませんでした。`MB_SETFOREGROUND | MB_TOPMOST` を付けたら見えるようになりました(開発メモのセッション11とセッション12)
- RC で `CHECKBOX … , BS_OWNERDRAW` と書くと、ボタンの種類を表す下4ビットが `BS_OWNERDRAW`(0x0B)になります(`BS_CHECKBOX` は 0x02)。実機では、タッチでも決定キーでもチェックが付きませんでした。チェックの状態を自分の変数で持ち、`WM_DRAWITEM` でその値を見て描く形にしたら直りました(開発メモのセッション21とセッション22、22 は 2026-08-25)
- `LB_SETTOPINDEX` は、下に空きができる位置へはスクロールしません。最後のページも先頭から見せるため、リストの最後に空の行を足して、行数をページの行数の倍数にしています(`ce_fileopen.c` の `FillFileList()`)(開発メモのセッション22、2026-08-25)
- ページを送るときは、`LB_SETTOPINDEX` を先に、`LB_SETCURSEL` をあとに呼びます。逆の順だと、ちらつきました(開発メモのセッション25)
- リストボックスで A〜Z のボタンを押すと、選択が動きました。`FileListCtrlProc` で、空白以上の `WM_CHAR` を元のリストボックスに渡さずに捨てています(開発メモの「v1.0.2 の2回目」、2026-10-07、コミット d58520e、タグ v1.0.2)
- メインメニューのボタンで決定キーが効きませんでした。ボタンのサブクラスで `WM_KEYDOWN` を見るだけでは直らず、`WM_GETDLGCODE` で `DLGC_WANTARROWS | DLGC_WANTALLKEYS` を返して、矢印キーでのフォーカスの移動と決定を自分で処理したら効きました(開発メモのセッション21とセッション22、22 は 2026-08-25)
  - この形にしたら、戻るキーでメニューが閉じなくなりました。`VK_ESCAPE` を自分で `IDCANCEL` に送ったら直りました(開発メモのセッション22、2026-08-25)
  - 使えないボタン(ROM を読む前のステートセーブなど)は、`IsWindowEnabled()` を見て飛ばします(開発メモのセッション22、2026-08-25)
- `SetPixel` で文字の点だけを描くラベルは、背景を消さないので、文字を変えると前の文字が残りました。文字を変えたら `InvalidateRect(hDlg, NULL, TRUE)` でダイアログ全体を描き直します(開発メモのセッション22、2026-08-25)
- RC の座標はダイアログ単位(DLU)で、画素ではありません。ファイル選択の一覧は、計算では6行のはずが10行見えたことがありました。1ページの行数は、実機で数えて決めます(今のコードは `CE_FILELIST_PAGE_SIZE` = 6)(開発メモのセッション22、2026-08-25)
- リソースのビットマップを `LoadBitmapW()` で読むときは、`WinMain` の `hInstance` を渡します。`GetModuleHandleW(NULL)` では読めませんでした(開発メモのセッション34、2026-09-25)
- アイコン(.ico)には AND マスクを入れます。Pillow で書いた .ico にはマスクが無く、Brain の画面でアイコンのまわりが黒くなりました。マスクを足したら直りました(開発メモの「v1.0.1 の2回目」、2026-10-02、コミット 884d269、タグ v1.0.1)

## ファイルとパス

- `loader.c` の `base()` は `/` で区切ります。CE のパスは `\` 区切りなので、そのままだとセーブのファイル名に ROM のパスが丸ごと入りました。`ALT_PATH_SEP` が定義されているときは `\` も見るようにしています(開発メモのセッション13、2026-08-18)
- `char *` のパスを `CP_ACP` で変換すると、日本語のフォルダ名が `?` に変わり、ファイルが開けませんでした(実機のログで `\Storage Card\???\…`)。パスは UTF-8 で持ち、`sys/ce/compat/stdio.h` で `loader.c` の `fopen()` を `ce_fopen_utf8()`(`ce_sys.c`)に置き換えて、`_wfopen()` で開いています。日本語のフォルダ名・ファイル名で開けることを実機で確かめました(開発メモのセッション13、2026-08-18)
- セーブのファイルは ROM と同じフォルダに作ります。ROM を読むたびに、`ce_main.c` の `LoadRom()` が `rc_setvar("savedir", …)` で ROM のフォルダに変えます(開発メモのセッション16、2026-08-24)
- ファイルが「無い」のか「あるのに開けない」のかは、`GetFileAttributesW` で分けます(`ce_sys.c` の `sys_file_state()`)。実機の値は、無いときが 0xFFFFFFFF(`GetLastError()` は 2)、あるときが 0x00000080 や 0x00000020 でした(開発メモの「v1.0.4 の1回目」、2026-10-09、コミット 2606485、タグ v1.0.4)
- 設定は `AppMain.exe` と同じフォルダの `PopGB.cfg` に書きます(`ce_config.c`)。起動しただけでは作られず、ROM を選んだときや設定画面を閉じたときに書きます(開発メモの「次の版の作業」、2026-10-03)

## 終わり方

- 終了と `die()` は `ExitProcess()` を直接呼びます。CRT の `atexit()` には頼らず、セーブの書き込みは `ExitProcess()` の前に呼んでいます(`ce_main.c` の `CeShutdown()`・`die()`)(開発メモの「実装したファイル一覧」)

## デバッグの進め方

- アプリが例外で落ちたときは、[Brain Exception Reporter(BER)](https://github.com/Sgch/ber) で例外とレジスタを記録しました(開発メモのセッション20)
- 落ちないのにおかしいときは、デバッグログ(Video Config の「デバッグログを有効にする」。既定は OFF)に見たい値を書き出すコードを足し、実機で同じ操作をして、ログを読んで直しました。日本語のフォルダ名の件と 170ms の件は、ログで原因がわかりました(開発メモのセッション13、2026-08-18、とセッション8)
- 40ms を超えたフレームは `doevents: slow frame gap=…` としてログに出ます。メニューやダイアログを開いていた時間もここに出るので、メニューの前後の行は除いて読みます(開発メモのセッション8とセッション15)
- 製作者が実機の結果を伝えるとき、同じ Brain に複数のエミュレータを入れていたので、どのアプリの画面かを取り違えたことがありました。「Input Config」などの言葉だけでは区別できないので、画面の写真やアプリの名前で確かめてから直します(開発メモのセッション14)
